# 06 Demo And Investor Readiness

## Design Agent Output

The demo should feel like an operating console for an AI delivery team, not a chatbot. The user should see agents, artifacts, and progress.

## Demo Experience

### First Screen

Core elements:

- Project requirements input
- Sample input button
- Run planning pipeline button
- Recent runs list

Tone:

- Calm
- Operational
- Trustworthy
- Enterprise-ready

Avoid:

- Overly playful chatbot UI
- Huge marketing hero
- Too many configuration controls
- Hidden outputs

### Run View

Core elements:

- Agent timeline
- Artifact tabs
- Implementation brief preview
- Execution, QA, deployment, and handoff status
- Live logs for Codex, QA, and deployment commands
- "Run Codex", "Save credentials", and "Deploy to Azure" actions behind explicit confirmation

The user should understand:

- What happened
- Which agent produced which artifact
- Why the next step is safe
- What the system needs before execution

## Demo Script

### 60-Second Version

1. "Teams lose time turning vague ideas into executable software plans."
2. "Agentic Delivery OS gives every project an AI delivery team."
3. "I paste a rough idea for a web app."
4. "The Intake Agent normalizes it."
5. "The Team Assembler picks the smallest useful team."
6. "Product and technical agents produce a workflow and implementation brief."
7. "The Codex Engineer Agent creates the starter project."
8. "The QA Agent tests it locally, in Docker, and in a real browser."
9. "The Deployment Agent can publish the generated app to Azure and verify the public URL."
10. "The result is not just code. It is a traceable delivery process."

### 3-Minute Version

1. Show the raw requirements input.
2. Run the planning pipeline.
3. Show event timeline.
4. Open intake brief.
5. Open staffing decision.
6. Open workflow plan.
7. Open implementation brief.
8. Trigger Codex execution or show a completed execution.
9. Show generated project files and execution summary.
10. Show QA report, browser transcript, screenshots, and Docker evidence.
11. Trigger Azure deployment or show a completed deployment summary.
12. Show the public URL, post-deploy QA, and handoff summary.
13. Close with enterprise value and extensibility.

## Investor Pitch

One-liner:

> Agentic Delivery OS is an autonomous AI delivery team that turns business ideas into scoped, staffed, and implemented MVPs.

Problem:

- AI coding tools are powerful but unstructured.
- Enterprises need repeatable delivery, not random prompt outputs.
- Agencies and product teams need faster project starts with better handoffs.

Solution:

- Agent roles mirror real delivery teams.
- Handoffs are structured artifacts.
- Execution is provider-neutral.
- Codex becomes the first worker backend.
- QA and deployment evidence make the output auditable.

Why now:

- Agentic coding models are getting strong enough to execute real work.
- Companies are looking for measurable AI productivity.
- The missing layer is orchestration, trust, and delivery process.

Market wedge:

- Internal tools
- MVP factories
- AI consulting delivery
- Enterprise innovation teams
- Product discovery to prototype workflows
